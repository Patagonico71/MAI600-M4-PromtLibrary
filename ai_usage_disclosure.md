## How I used AI

**ChatGPT** — English writing support. I work through problems in Spanish first, so I used it to translate my notes and to correct grammar and phrasing in the README and the prompt library.

**Gemini and Claude** — code support. Word-count filtering of the dataset candidates, structuring the CSV files, and the analysis notebook that aggregates my scores and draws the charts.

**Gemini** — the model under test. 19 of the 20 outputs in `results_table.csv` were generated by pasting each prompt into a fresh Gemini chat with one case substituted in. The twentieth (T2 / P4) came from ChatGPT, because Gemini declined that prompt on the first attempt; it answered on retry, and the `model` column in the results table records which model produced each row.

**Claude** — helped design the five-prompt progression and draft the prompt text itself, which is the artifact this assignment is about. Worth stating plainly rather than burying: the prompt wording started as AI-assisted drafts. What makes them mine is the testing — I ran them, saw where they failed, and the revisions came from those observed failures.

## What I changed or corrected

- **Re-ran T4 / P5.** The first attempt returned "Missing information: The text of the request", which meant the message had not pasted. I checked the block, re-pasted it in a new chat in a different browser, and used the second result. The truncation was mine, not the model's — P5 is the longest prompt in the library and the easiest to cut when copying.
- **Discarded a T1 / P1 run.** The output came back with the five field names from P5, including "Topics mentioned", which P1 never asks for. That meant the chat had inherited the format from an earlier prompt. I re-ran it in a clean chat and used that result instead. Without catching this, P1 would have scored artificially well and ruined the comparison the whole project depends on.
- **Switched models for one output.** Gemini declined P4 on T2 on the first attempt, so I ran it in ChatGPT. It later answered the same prompt on retry, so I recorded the refusal as transient rather than as a failure mode of the prompt, and added a `model` column to the results table so the one cross-model row is visible rather than hidden.
- **Redesigned the output schema after reading the cases.** My first draft had "Requested by" as patient or caregiver only. Reading the ten messages showed that one is a student writing a research report and one is a health professional asking about a child on their caseload, so a binary field would have been wrong on a fifth of the set. I added "Health professional" and "Student or researcher".
- **Added the escalation route for the same reason.** T2 asks about a diet's success rate while mentioning that seizures have tripled in two weeks. Without a "Route to clinical staff" value, every prompt would have filed it as a routine information request.
- **Corrected my own analysis of P4's "Not stated" defect.** My first read was that the evidence rule was too strict and should be loosened. Noticing that P4 got T4 right — the one case with an explicit "I am a student" — changed the diagnosis: the rule is too literal, not too strict. The fix in P5 states that a description counts as evidence, rather than weakening the rule.
- **Fixed a bug in the analysis notebook.** The validation cell used `df[ALL].between(1, 5)`, which fails on the pandas version I ran it under. I replaced it with an explicit comparison and re-ran the notebook end to end.
- **Rewrote the reflection section entirely in my own words**, from my own notes on what I observed while scoring.
